# Прототип анализа фонограмм — версия на C++/Qt

Порт питоновского прототипа на C++17 и Qt 6. Структура файлов повторяет
исходную, чтобы можно было сверять реализации построчно.

## Сборка в контейнере (ничего не ставится в систему)

```bash
./dev.sh build           # собрать
./dev.sh run             # собрать и запустить окно
./dev.sh test запись.wav # самопроверка без окна
./dev.sh shell           # оболочка внутри контейнера
```

Исходники подключены как том, так что редактируете на хосте обычным редактором,
а собирается всё внутри. Результат сборки лежит в `build-docker/` — отдельно от
хостового `build/`, чтобы они не мешали друг другу.

Окно рисуется через X11 хоста: `dev.sh` сам вызывает `xhost +local:docker`.
Сеть общая с хостом, поэтому приложение видит SRW на `localhost:8000`.
Звук идёт через сокет PulseAudio; на Wayland без XWayland окно может не
открыться — тогда либо ставьте `xwayland`, либо собирайте в контейнере,
а запускайте на хосте.

Пользователь внутри контейнера создаётся с вашими идентификаторами, иначе
собранные файлы оказались бы во владении root.

## Сборка в системе

```bash
sudo apt install build-essential cmake qt6-base-dev qt6-websockets-dev \
                 zlib1g-dev ffmpeg

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
./build/audio_forensics
```

Внешних зависимостей, кроме Qt и zlib, нет: FFT, спектрограмма, отрисовка
и запись DOCX написаны здесь же.

Самопроверка без диалогов — прогоняет загрузку, анализ, снимок окна и отчёт:

```bash
./build/audio_forensics --selftest запись.wav
# /tmp/selftest_window.png и /tmp/selftest_report.docx
```

## Файлы

| Файл | Что делает | Питоновский аналог |
|---|---|---|
| `config.h` | все настройки | `config.py` |
| `analysis.*` | чтение файлов, STFT, детектор-заглушка, классические проверки | `analysis.py` |
| `plots.*` | отрисовка на QPainter и виджет `PlotView` | `plots.py` |
| `detectors.*` | детекторы с общим интерфейсом | `detectors.py` |
| `service.*` | клиент SRW: HTTP и websocket | `service.py` |
| `player.*` | воспроизведение через ffplay | `player.py` |
| `report.*` | сборка заключения | `report.py` |
| `docx.*` | запись DOCX вручную | заменяет python-docx |
| `batch.*` | пакетная обработка папки | `batch.py` |
| `mainwindow.*` | окно и весь сценарий работы | `app.py` |

## Чем отличается от питоновской версии

- **DOCX пишется руками.** Замены python-docx в C++ нет, поэтому пакет OOXML
  собирается из нескольких XML и складывается в zip без сжатия. Word и
  python-docx такие файлы читают.
- **Своё БПФ.** Вместо numpy — преобразование по основанию 2; длина
  дополняется нулями до степени двойки, поэтому шаг по частоте в проверках
  вроде частоты среза чуть отличается от питоновского (на тесте 1101 против
  1100.9 Гц).
- **Пересчёт частоты для потока** сделан фильтром нижних частот и линейной
  интерполяцией вместо `scipy.resample_poly`. На вход модели идёт тот же
  16 кГц моно int16.
- **ONNX-детектора нет.** В питоне он опирался на onnxruntime; для C++ нужно
  подключать её отдельно. Каркас готов: добавляется класс в `detectors.cpp`.
- Фоновые задачи на `QtConcurrent` вместо `QThread`.

## Что проверено

Собрано и прогнано на Qt 6.4, Ubuntu 24.04:

- загрузка wav, mp3 и видео с извлечением дорожки;
- спектрограмма и кривая оценок совпадают с питоновскими по числам
  (144000 отсчётов, спектр 257×561, 15 оценок, dc и срез сходятся);
- пакетная обработка папки, включая битый файл — он уходит в колонку ошибок;
- отчёт открывается python-docx: таблицы, картинки и журнал на месте.

Не проверено вживую: работа с сервисом SRW — контейнеров в среде сборки нет.
Код клиента повторяет питоновский, но первый запуск стоит делать с логами.
